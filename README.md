# PuzzleMixEscape

**English** | [简体中文](README.zh-CN.md)

**PuzzleMixEscape is a benchmark of 94 interactive 3D escape rooms for multimodal models.** It tests whether a model can find clues from a first-person view, reason about spatial relationships, and act on what it discovers. In *Maintenance Store* (L2-01), for example, the model must move around to count scattered coloured balls and relate them to a note, a toolbox, and a ventilation grille. An episode succeeds only when the model opens the unlocked exit door.

## Levels and evaluation protocol

The four groups vary along two axes: **exploration difficulty** and **puzzle complexity**. The medium groups are not successive difficulty tiers: `medium-a` spreads clues across a larger space, while `medium-b` makes the puzzles more demanding without increasing the exploration scope.

| Difficulty | Level IDs | Levels | Action budget | Baseline Recall budget | Tip threshold |
|---|---|---:|---:|---:|---:|
| easy | [L1-01 to L1-39](level/easy/) | 39 | 150 | 10 | 25 |
| medium-a | [H1-01 to H1-11](level/medium-a/) | 11 | 200 | 20 | 50 |
| medium-b | [L2-01 to L2-22](level/medium-b/) | 22 | 200 | 15 | 40 |
| hard | [H2-01 to H2-22](level/hard/) | 22 | 250 | 25 | 60 |

At each decision, the baseline model receives a 640 × 360 first-person image, its inventory, its notes, and the last 10 interactions. **Recall** retrieves earlier observations without consuming an environment action. After the specified number of consecutive actions without progress, the environment appends a **Tip** to the action feedback. This happens at most once per episode and costs neither an action nor a Recall. Finding the key or unlocking the exit is not enough to succeed; the door must open, but the model need not walk through it.

## Setup

The native environment uses **Python 3.11, OmniGibson 3.9.1, and Isaac Sim 5.1**, and requires a compatible NVIDIA RTX GPU and driver. Follow the [BEHAVIOR installation guide](https://behavior.stanford.edu/getting_started/installation.html) to install the simulator. For reproducibility, the [simulator source revision used for this benchmark](https://github.com/StanfordVL/BEHAVIOR-1K/tree/78980ee463b900226e48b956ae53a6f799ad8cc1) is available.

Activate the simulator's Python environment and run the following commands **from the root of this repository**. The examples use L2-01.

```bash
python -m pip install -r evaluation/requirements.txt
python setup_assets.py --level L2-01
```

The installer downloads assets from their official sources to `assets/datasets/`. L2 and H2 rooms are generated by code in this repository and require the robot assets. L1 and H1 also require the BEHAVIOR house and object dataset; the first download is larger and prompts you to accept its terms. Installed assets are reused across levels.

**Check the installation without an API key.** The following command runs the reference solution in the native L2-01 scene and opens the exit. Use it to check rendering and interaction, not to measure model performance.

```bash
python run.py --level L2-01 --standard
```

## Model evaluation

Each invocation evaluates **one level**, selected with `--level`. To evaluate GPT-6-Astra via the OpenAI API, enter your own key in PowerShell 7 and run:

```powershell
$env:OPENAI_API_KEY = Read-Host "OpenAI API key" -MaskInput
python run.py --level L2-01 --provider openai_official --model gpt-6-astra --confirm-medium --live --out l2-01-gpt-6-astra
```

Use `--confirm-medium` after confirming that the selected model supports medium reasoning effort. Only `--live` sends requests to the provider and may incur charges. For another level, change `--level` and use a fresh run name for `--out`, or omit `--out` for a timestamped name. To inspect a level's configuration and budgets without starting the simulator or calling a model, run `python run.py --level H2-03`.

| Provider (`--provider`) | API key environment variable | Model settings |
|---|---|---|
| `openai_official` | `OPENAI_API_KEY` | Responses API with image input and `medium` reasoning effort |
| `openrouter` | `OPENROUTER_API_KEY` | Use a `provider/model` ID with `medium` reasoning effort; set `PUZZLEMIX_OPENROUTER_PROXY` |
| `dashscope` | `DASHSCOPE_API_KEY` | `qwen3.8-max` with thinking enabled and `thinking_budget=1024`; omit `--confirm-medium` |

## CoordMem

CoordMem calls a memory agent before the action agent at each decision. In `selective` mode, the action agent receives only the records chosen for that step; in `full` mode, it receives all active records. Both agents use the selected provider and model. The action agent has **no independent Recall** in either mode. Action budgets, the Tip policy, and the success condition are the same as for the baseline.

```powershell
python coordmem/run.py --level L2-01 --mode selective --provider openai_official --model gpt-6-astra --confirm-medium --live
```

Replace `selective` with `full` to switch modes. A normal decision step makes two potentially billable requests. See the [CoordMem method notes](coordmem/README.md) for the memory record format and output files.
